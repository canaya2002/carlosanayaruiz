01 — What was actually broken

Nine defects that were shipping

Not style opinions. Each of these was verifiable against the running site, and each is verified fixed against a production build. The measurement column is the proof, not a claim.

Open Graph images were the wrong shape

og-es.png, og-en.png and og-default.png were 1000×1000 squares. The metadata declared all three as 1200×630. Every social and AI link preview was reading a dimension that did not match the file.

OG images are now generated per page and per locale by next/og, so the declared size and the produced pixels cannot disagree. Eleven routes, both locales, all prerendered — so the build renders and validates every card.

favicon.ico was a 517 KB PNG

Renamed, not converted. Every icon in public/ was the same 1000×1000 source at ~517 KB regardless of role — icon-192.png was not 192 px, apple-touch-icon.png was not 180. The headshot was 2.26 MB rendered at 80 px.

All regenerated at their real sizes by scripts/generate-assets.mjs, including a genuine multi-resolution ICO at 16/32/48.

Structured data claimed a site search that does not exist

The WebSite node declared a SearchAction pointing at /contacto?q={search_term_string}. There is no site search. It also used the Spanish path on English pages.

Removed. Also removed: dateModified: new Date(), which made every page claim it changed on every deploy, and the identical lastModified stamp on every sitemap URL. Manufactured freshness teaches a crawler to ignore the field.

Three of four services had a slug that matched no route

data/services.ts carried a free-text slug per locale. aplicaciones-web-nextjs-firebase against a real route of /desarrollo-web; automatizacion-ia-chatbots against /automatizacion-ia; dashboards-responsivos against /dashboards. Those slugs built schema @ids and canonical URLs.

Replaced with route: RouteKey referencing a single ROUTES table. The drift is now a compile error rather than a silent wrong URL.

Unprefixed URLs were hard 404s

The middleware matcher was ['/', '/(es|en)/:path*'] — it only ever saw URLs that already had a locale prefix. /sobre-mi never reached next-intl and 404'd instead of redirecting. Every inbound link that dropped the prefix was a dead end.

The image optimizer was an open proxy

images.remotePatterns allowed { protocol: 'https', hostname: '**' }. Anyone could pass any URL on the internet through /_next/image on this domain, consuming the transformation quota and laundering third-party content through the brand.

Removed entirely — every image is local. Added a CSP, and firestore.rules, without which both form collections are world-readable.

Dark mode was dead code

tailwind.config.ts declared darkMode: 'class', but Tailwind v4 never loads a JS config without an @config directive. The whole file was inert — as was a second, duplicate PostCSS config, and a Playfair Display that no rule referenced but every visitor downloaded.

Real token-level theming now, applied before first paint so there is no flash. Seven font files became two.

The home page competed with its own service pages

It rendered all twelve service FAQs, marked up as FAQPage — the same questions and answers as the four service pages, under a different URL. Two pages answering one query is how they end up ranking against each other.

Split: home owns six engagement-level questions, each service page owns its own technical ones. Verified zero cross-page duplication across 44 questions in both locales.

was12 duplicated now0 duplicated

Your own diagnostic tools were being served a different page

A Disallow: /_next/static/chunks/ rule applied to every crawler without its own group — which includes Google-InspectionTool, so URL Inspection and the Rich Results Test, plus Lighthouse and PageSpeed Insights. They would have rendered a JS-stripped DOM that differs from Googlebot's.

Dropped. robots.txt now names Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, PerplexityBot, ClaudeBot and Google-Extended explicitly, so each is greppable rather than assumed.

02 — Accessibility

Three contrast failures, measured not eyeballed

Every ratio below was computed from the oklch tokens through sRGB to WCAG relative luminance. Two of these I introduced in the new design system by using recessed tokens at body size; all three were caught before launch.

Token Used for Before Floor After
--ink-subtle Body copy at text-sm 3.45 4.5 4.89
--accent Metric labels, badge text 4.24 4.5 5.12
--accent on its wash Badge on tinted ground 3.81 4.5 4.61
--line-control new Input, textarea, outline button borders 1.55 3.0 3.64

That last row is the interesting one. A divider and a form-field border had been sharing one token. WCAG exempts purely decorative boundaries from a contrast floor — which is correct, and the editorial look depends on hairlines being barely there — but an input's border is the affordance telling you where the field is, so it is governed by 1.4.11 non-text contrast at 3:1. Collapsing the two jobs into one token is exactly how a 1.55:1 input border ships without anyone noticing.

Also verified across all 22 URLs: exactly one <h1> per page, no skipped heading level, a working skip link, correct lang, and no icon missing aria-hidden. The locale switcher was a <button>, so the alternate-locale URL existed nowhere in the page and could not be middle-clicked — it is now a real anchor with hrefLang.

The honest gap

The site has no articles. Sections 15, 18, 36 and 41 all converge on original, non-commodity content demonstrating real experience — and that is the single largest remaining opportunity, worth more than anything left in the code.

I deliberately did not generate any. Section 50 forbids publishing unreviewed AI output and section 15 requires actual experience; a dozen synthetic posts about Core Web Vitals would have made the checklist look more complete while making the site materially worse. What I shipped instead is the structure that content will hang from: a real /servicios hub, so the four service pages sit in a Home → hub → service hierarchy instead of floating.

You have the raw material and almost nobody else in this niche does — the migration that lost 40% of its traffic because nobody mapped the URLs, the platform with half its pages blocked by a misconfigured robots.txt. 06 — Verification

How this was checked

Against a production build, not source

Grepping source tells you what someone intended. Every claim in this report was measured by building the site, serving it, and reading the rendered HTML — because the OG routes were initially marked dynamic, which means the build was not executing them at all and a rendering failure would have reached production unseen.

  • Type — tsc --noEmit --incremental false, exit 0. Non-incremental on purpose: a stale .tsbuildinfo can mask a whole error class.
  • Build — next build, exit 0. All 33 routes prerendered; nothing dynamic but the proxy.
  • Routes — 22 pages, 11 OG cards, sitemap, robots, manifest, llms.txt: all 200. Both 404 boundaries return real 404s.
  • Schema — every block JSON-parsed, 111 nodes, zero dangling @id, zero aggregateRating / review / priceRange / SearchAction.
  • Previews — fetched the exact og:image URL each page declares; all return image/png. Confirmed English pages now serve English alt text, which they did not.
  • Colour — recomputed every oklch→sRGB conversion independently and compared against the values actually shipped in the built stylesheet.
  • SERP — all 44 title and description lengths measured twice, independently, on separately-built servers. Identical row for row.

Two findings I rejected

Automated review surfaces plausible-sounding problems that are not problems. Both of these came from my own checks and both were false.

  • Offer nodes on every page. Read as an invented price. They are OfferCatalog → Offer → itemOffered: Service carrying a name and a URL and nothing else — the correct way to declare a catalogue without inventing pricing. A substring grep for "Offer" was too blunt.
  • dateModified equal to today. Read as the fabricated-freshness bug returning. It comes from a LAST_UPDATED constant on pages genuinely authored today, and the visible date on the page matches. It will not drift.

Worth stating because the opposite error — accepting a confident finding without checking — is how a correct implementation gets “fixed” into a broken one.
